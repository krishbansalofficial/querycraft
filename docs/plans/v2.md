# Plan v2: from fine tuning study to text to SQL analytics agent

Status: laptop parts done 2026-11-23; 7B rows wait for the Kaggle notebooks. Compute plan: [v2_compute.md](v2_compute.md). v1 results, configs and the
split are unchanged; v2 configs live in `configs/retriever`, `configs/agent`, `configs/serve`.

## Rules carried over from v1

* Every choice is made on val. Dev and held back are only scored. `querycraft.data.selection` marks code that makes
  a choice; inside it `load_split` refuses dev and held back, and `tests/test_v2_selection.py` fails if a marked
  function names those splits or if a v2 entry point (retriever sweep, abstain fit, agent tune) is not marked.
* Every number in the README comes from `runs/` through `querycraft/report.py`, with a paired exact sign test or a
  95% interval. Unmeasured is TBD.
* $0: laptop, Kaggle, Colab free, Modal free credit under `querycraft/budget.py`.

## Decisions (made without asking, with the reason)

| # | Decision | Why |
|---|---|---|
| 1 | Bi encoder base: `BAAI/bge-small-en-v1.5` (33M, MIT) | Strongest small English retrieval model of its size class we know of; 384 dims keeps FAISS tiny; fast enough on CPU that serving needs no GPU for retrieval (the GPU is busy with vLLM). |
| 2 | Cross encoder base: `cross-encoder/ms-marco-MiniLM-L6-v2` (22M, Apache 2.0) | Reranks 10 candidates per question in milliseconds on CPU. A bigger reranker (bge-reranker-base, 278M) was the alternative; not tried, to keep serving on CPU. |
| 3 | Bi encoder loss: cached multiple negatives ranking (GradCache), batch 64, chunks of 16, plus one mined hard negative per pair from the same database | The plain loss at batch 64 filled 8 GB and spilled to system memory (13 s per step). GradCache gives the same 64 way in batch negatives at 2.3 GB, 1 s per step. |
| 4 | Retriever knobs (bi or reranked list, k in 2..5, one foreign key hop or not) chosen by the SFT model's second pass val EX, not by recall | The goal is EX. Recall alone always prefers larger k. Ties go to fewer tables. |
| 5 | Table text = name + columns with types + the 3 example values the prompt already shows | Same evidence the SQL model sees; no extra database reads. |
| 6 | Agent: a fixed state machine chooses the tools; the model only writes SQL | The SFT model was trained to output bare SQL and never saw tool call syntax. Free form tool choice would test an untrained format, not the agent idea. |
| 7 | Agent counts an all NULL result as empty | An aggregate over zero matching rows returns one NULL row; without this the agent never repaired the most common empty result case (caught by `tests/test_agent_tools.py`). |
| 8 | Abstain model decides over the existing v1 vote answers (T = 0.6) | Then the learned model and the vote share baseline rank exactly the same SQL; only the score differs, so the paired comparison is clean and costs no GPU. |
| 9 | Abstain comparison at a fixed 70% of dev answered, ties broken by a seeded shuffle; also reported at the val chosen thresholds | Equal coverage makes accuracy directly comparable; vote share has many ties (multiples of 1/8). |
| 10 | Kaggle runs read code and data from private datasets, not from GitHub | Nothing has to be pushed before a notebook can run. |
| 11 | The val sweep chose the bi encoder's top 2 tables + one foreign key hop (val EX 35.6; every reranked setting scored 31.2 to 34.4) | Decided by the rule in #4, not by recall: the reranked lists keep more gold tables at a fixed k but the hop on a short list shows the model the join tables it needs. Reported as is. |
| 12 | Iowa Liquor Sales from a CC0 Kaggle mirror of calendar 2022 (`leonczarlinski/iowa-liquor-sales`), first 2,000,000 invoice lines (2022-01-02 to 2022-10-19), star schema of 6 tables | The official Socrata endpoint returned 404 on 2026-11-23 (portal moved to the Iowa Data Hub). The script tries it first. Six tables make table retrieval matter. |
| 13 | The 30 Iowa questions are a report only split (`iowa`, in `data.REPORT_ONLY`) | It is a second held back set; the selection guard refuses it like dev. |
| 14 | The 7B agent reuses the options the 1.5B tuning chose on val | Running the 4 setting val grid at 7B would cost about 3 Kaggle hours. The choice is still made on val. |
| 15 | Agent latency: amortized over the batched run, plus 50 dev questions timed one at a time (agent and its own first attempt) | The batched run sends one model call per round for all questions, so per question wall clock only exists in the unbatched sample. |
| 16 | The CI gate replays cached completions keyed by the exact prompt hash, and compares result hashes (ordered and multiset) recorded with the real databases | CI has no GPU and no BIRD databases (41 GB). Replay still exercises prompt building, pruning, linked tables, the chat template, SQL extraction and the match rule. Margin 1.0 point (2 of 200). |
| 17 | The API's confidence is the learned abstain model's probability, computed from 8 votes on the v1 prompt and the retriever scores; the API answers with the agent's SQL | The model was calibrated on vote answers; its calibration on agent answers is measured separately (TBD until the agent run exists). |
| 18 | Serving benchmark: bf16 (base + LoRA adapter, as served) against AWQ W4A16 of the merged model, llm-compressor in its own venv, calibrated on 256 val prompts | AutoAWQ is deprecated; llm-compressor's compressed tensors format is what vLLM serves. A separate venv keeps its pins away from the evaluation stack. |
| 20 | AWQ calibration cut to 64 val prompts of up to 1,024 tokens (1.5B on the laptop and 7B in notebook C) | 256 x 2,048 spilled past 8 GB: 32 s per AWQ grid step, about 20 h. The cut ran in 188 s at 5.1 GB. The accuracy loss is reported with this calibration; a larger one might lose less (not measured). |
| 21 | Benchmark adds a third variant, the same bf16 weights merged | The first run compared base + adapter with a merged AWQ model, mixing two effects. The first run is kept in `runs/bench_qwen1.5b_first`; the README reports the three variant run. |
| 22 | The demo page shows the real 8 vote count and, from the v2 API, the calibrated confidence and threshold | The first adapter mapped confidence onto "N of 100 sampled queries agree", which was false. |
| 19 | Docker compose tested on the laptop, never deployed to a cloud | Three fixes were needed on a CUDA 12.6 driver: the `v0.32.0-cu129` vLLM image (the default tag needs CUDA 13), `NVIDIA_DISABLE_REQUIRE=1` (minor version compatibility, as in the venv), and removing torchcodec (the v1 crash). |
| 23 | Kaggle notebooks run in an isolated Python 3.12 venv with the laptop's exact stack | Kaggle's image is Python 3.13 with preinstalled torchaudio and torchao built for its own torch; mixing in torch 2.13 crashed transformers, then peft. Kaggle also drops the top folder of a single uploaded zip; setup handles both layouts. |

## Results (all in the README, generated by `querycraft/report.py`)

| Part | Beat its baseline? |
|---|---|
| 1 Retriever | Recall yes (94.8% vs 82.3% of dev questions keep every gold table); EX no (43.22 vs 43.94, p = 0.29) |
| 2 Abstain | Calibration yes (ECE 0.094 vs 0.137); selective accuracy no (59.18 vs 59.46 at 70%, p = 0.79) |
| 3 Agent | Yes against its own single pass (44.59 vs 43.22, p < 0.001); no against the v1 model (p = 0.36) |
| 4 Serving | AWQ 2.2x faster at 1 user, but 4.2 dev points worse (p < 0.001) |
| 5 Gate, monitoring | Working: gate reproduces 38.0 and fails on a one word prompt change; drift flags the warehouse traffic |
| 6 Warehouse | 30 questions: agent 50.0 vs 46.7 (p = 1.0); needs human review |
